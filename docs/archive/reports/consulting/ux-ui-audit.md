# Storefront UX/UI Audit

**Scope:** customer-facing storefront only (landing → browse → PDP → wishlist → cart → checkout → confirmation → tracking → account → auth). Admin is out of scope.
**Branch:** `fixes` @ `12539c6`
**Method:** read-only code review of `resources/js/**` (non-admin), the controllers/routes/models that feed them, and `lang/*.json`. `npm run types` passes for all storefront files (the only errors are in `pages/Admin/Products/Create.tsx`). Nothing was run in a browser. Where a finding depends on runtime behaviour I couldn't observe, it is marked **(uncertain)**.

---

## 1. Executive summary

- **Customers who sign in lose their cart.** Guest carts are keyed by session ID, and login regenerates the session. After login the user's cart is looked up by `user_id`, and nothing merges the two. The cart's own "Sign in to continue" button (and the forced sign-in when guest checkout is disabled) therefore empties the basket and drops the user on `/dashboard` instead of checkout. This is the biggest conversion leak in the codebase.
- **Server messages are never shown on the storefront.** `FlashToaster` is only mounted on admin layouts. Contact-form success/failure, "Unable to create checkout session", "guest checkout disabled" and Google-login errors all disappear. The Contact and Login pages read props (`success`, `error`) that the backend never sends. On the Pay button, a backend failure looks like a button that does nothing.
- **The browse experience has functional bugs, not only polish issues.** Picking a category applies the *previously* selected category (stale closure). Picking a price range quietly removes the search term and sort order. The desktop header has no navigation and no search. Home-page product cards need two taps on mobile and then do a full page reload.
- **The product page undermines trust.** Every product shows **0 stars and "(0 reviews)" in hardcoded English**, even when reviews exist. Reviews are collapsed by default. There is no description or specs section, and nothing on shipping cost, delivery time, returns or "incl. VAT". The wishlist heart always starts as "not saved".
- **Checkout is a bare form with no order summary.** The line items are never rendered. There is no `<form>` and no `autocomplete`, so mobile autofill is poor. Validation runs through 5-second toasts with no field-level errors. Shipping cost doesn't react to the selected country. Terms and legal links are missing from the payment step (no footer on checkout).
- **Post-purchase tracking is underbuilt despite the backend being ready.** The account Orders page shows the internal DB `id` instead of the `order_number` used in emails. The tracking number is plain text: `Order::trackingUrl()` and the synced Spediamo status are only used in emails. The "Orders" link in the header menu goes to `/orders`, which is a 404. When order creation lags behind payment, the Success page sits behind a full-screen spinner that never clears.
- **i18n and accessibility are uneven.** de/fr/es are missing 16–17 keys used in cart and checkout, and the translator has no per-key English fallback, so customers see raw keys like `cart.coupon_placeholder_input`. Register, password reset, verification, the checkout Cancel page, review writing and account settings are hardcoded English, and the variant selector is hardcoded **Italian**. The whole storefront has exactly one `aria-label` on a button-like control, and icon-only buttons (cart, wishlist, account, menu, quantity, delete, gallery arrows) have no accessible name.
- **The hero hurts performance.** It loads a 1.9 MB PNG blurred with a CSS `filter`, plus the same 395 KB PNG twice, while a 50 KB `angeleye.webp` sits unused. The ring animation runs continuously with `respectReducedMotion={false}`. No image on the storefront uses `loading="lazy"`.

## 4. Strategic recommendations

1. **One storefront shell.** Create a persistent `StorefrontLayout` (Inertia persistent layout) with header, footer, flash toaster and mini-cart. Today Home duplicates the footer, nine pages have none, and every page re-mounts `<Header>`, which re-fetches the cart and wishlist counts on each visit. The shell should include a desktop nav (Shop, categories, Help), header search, an account dropdown (Orders, Wishlist, Logout) and a cart **drawer** for add-to-cart confirmation. This fixes H10, M2, M6 and L1 in one go.
2. **Cart continuity and auth-in-flow.** Merge guest carts on login and registration, preserve the intended URL, and add an inline "Have an account? Sign in" panel in checkout instead of bouncing to `/login`. Reconsider requiring `verified` for checkout, and offer "Create an account with this order" on the success page that reuses the guest email (C1, M16).
3. **Checkout redesign.** Use a two-column layout: a form (contact → shipping → optional notes and coupon) and a sticky order summary with items and variants. Use real `<form>` semantics, autocomplete tokens, inline `useForm` errors, country-aware shipping recalculation and a saved address book for logged-in users. Add a terms/withdrawal acknowledgement line and trust row (secure payment, accepted methods, returns window) at the Pay button. Treat the Stripe hand-off as a navigation state so the button can't be pressed twice (H1, H2, M6, M8, M17).
4. **One order-detail experience.** Unify `Dashboard/Orders` and `Orders/GuestShow` into a shared `OrderDetail` component. Include the order number, a status timeline that handles cancelled and refunded orders, carrier name, the live Spediamo status with last-sync time, a "Track with carrier" link, line items with variants, the address, a VAT breakdown and an invoice/receipt download. Add a public "Find my order" form (order number plus email) that re-sends the secure link. Today `GuestInvalid` only offers "contact us" (H6, H7).
5. **Product page content model.** Add a description and specs accordion, a rating summary with a visible review list, variant swatches with sold-out states, a swipeable zoomable gallery, an "incl. VAT · ships in X · Y-day returns" line under the price, and back-in-stock capture. Use one price source across Home, listing and PDP ("from €X" for multi-price products) (C4, M7, M14, M19, M21).
6. **i18n hardening.** Server-authoritative locale (sync on first detection). Per-key English fallback. A CI parity test across the five locale files. An ESLint `no-literal-string` rule for storefront code. Translate remaining auth, checkout-cancel, review and settings screens. Translate category names in data rather than through key lookup (H8, H9, M10, L9).
7. **Design-system consolidation.** Decide light-only storefront or fully token-themed. Replace the hundreds of `bg-white text-black text-gray-900` overrides with semantic tokens. Standardise one card style, one primary button style and one quantity stepper (there are four ad-hoc steppers: QuickView, PDP, cart and the home card). Use shadcn primitives (Accordion, Sheet, Carousel, RadioGroup) instead of hand-rolled versions (M12, L5).
8. **Performance budget for the landing page.** Set an LCP target under 2.5 s on 4G. Use responsive AVIF/WebP, `fetchpriority` on the hero, lazy-load below the fold, set intrinsic sizes to prevent CLS, honour reduced motion and pause the hero animation when off-screen. Give the hero a real value proposition headline: today the only visible copy is the "Shop now" button, and the H1 is `sr-only` (`home.tsx:182`).
9. **Accessibility programme.** Run an axe pass per page. Label all icon controls, manage focus for menus and dialogs, check contrast (gray-300/400 text on white), give quantity steppers labelled live values, and make the rating input a radio group. Add a Playwright + axe smoke test on Home, PLP, PDP, cart and checkout.
