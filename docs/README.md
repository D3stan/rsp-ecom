# Documentation

This repo's docs are written for AI agents first and people second: short, path-anchored, and only about what the code cannot say.

## Where things live

| Kind of knowledge | Home |
|---|---|
| What exists and how it connects | the code, and the `graphify` knowledge graph in `graphify-out/` |
| Why, rules that must hold, traps, how to operate one area | `.ai/rules/<area>.md` (loaded by agents when they touch matching paths) |
| Facts about one function or class | its PHPDoc / JSDoc |
| Rules every agent session needs | `.ai/guidelines/*.md` |
| Multi-step procedures (e.g. deploying) | skills in `.ai/skills/` |
| Release and incident procedures | `docs/runbooks.md` |
| Third-party API references | `docs/vendor/` |
| In-flight plans and specs | `docs/superpowers/` (deleted when the work lands) |

`CLAUDE.md`, `AGENTS.md`, `.ai/rules/index.md`, `.ai/rules/boost/`, `.claude/skills/` and `.agents/skills/` are generated by `php artisan boost:update` from the sources above. Never edit them by hand.

## Rules

- Update the area doc in the same change as the code it describes. If a doc contradicts the code, the code wins: fix the doc.
- Area docs stay under 120 lines and list at most a few broad `paths:` globs (one per line, no `{a,b}` braces).
- No history, reports or finished plans in the tree. Old material is in git history; the pre-restructure docs are under the tag `docs-archive-2026-10-28`.
- The repo is public: no secrets, internal IDs, backup status or lists of known weaknesses.

## Checks

- `python3 scripts/docs_check.py` (also in CI): globs match files, mentioned paths exist, code comments point at docs that exist, size caps.
- CI also runs `boost:update` and fails if a generated file differs from what is committed.
