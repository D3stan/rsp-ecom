# Project documentation

RSP is an e-commerce shop for LED motorcycle headlights (EU, prices in EUR incl. VAT): Laravel + Inertia React, Stripe, Spediamo/DVA Express shipping.

Where each kind of knowledge lives (one home each; never duplicate across them):
- What exists and how it connects: the code and `graphify`. Columns: `database-schema`. Routes: `php artisan route:list`. Package docs: `search-docs`.
- Why, rules that must hold, traps and how to operate one area: `.ai/rules/<area>.md`, routed by `.ai/rules/index.md`. For a question about a subsystem, read the matching area doc before graphify or code.
- Facts about one function or class: its PHPDoc/JSDoc. Write the why, rules and traps there, never what the code already says, history or TODOs (use a GitHub issue).
- Multi-step procedures: skills in `.ai/skills/`. Incident and release procedures: `docs/runbooks.md`. Third-party API references: `docs/vendor/`.
- In-flight plans and specs: `docs/superpowers/`. When the work lands, move its lasting facts into the area doc or code comments and delete the plan in the same change.

Keeping docs true:
- If a doc or comment contradicts the code, the code wins: fix the doc in the same change.
- When you change code covered by an area doc, update that doc in the same change. When you change a function, re-read its docblock and fix it if it is now wrong.
- Edit only `.ai/guidelines/`, `.ai/rules/` (not `index.md`), `.ai/skills/` and `docs/`. `CLAUDE.md`, `AGENTS.md`, `.ai/rules/index.md`, `.claude/skills/` and `.agents/skills/` are generated by `php artisan boost:update`.
- Area docs stay under 120 lines. Run `python3 scripts/docs_check.py` after editing docs.
